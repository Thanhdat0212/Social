\# Social UI Design



\## Purpose



Create a coherent, product-specific Social interface that feels intentionally designed rather than generically generated by an AI.



\## Core Principles



\- Prioritize usability over decoration.

\- Preserve and extend the existing design system.

\- Do not blindly create new components when reusable components already exist.

\- Every major visual decision should have a purpose.

\- Keep visual hierarchy clear.

\- Design for real user flows, not isolated screenshots.



\## Avoid Generic AI UI



Avoid:



\- Generic SaaS dashboard layouts

\- Excessive rounded cards

\- Excessive glassmorphism

\- Random gradients

\- Purple gradients by default

\- Excessive shadows

\- Decorative elements without purpose

\- Excessive animations

\- Huge headings without useful hierarchy

\- Putting every piece of content inside a card

\- Repeating the same visual pattern everywhere



\## Before Coding



Before implementing a UI:



1\. Inspect the existing frontend.

2\. Understand the current page and user flow.

3\. Find existing reusable components.

4\. Identify existing typography, colors, spacing and design tokens.

5\. Identify UX problems.

6\. Define the visual hierarchy.

7\. Consider responsive behavior.

8\. Consider loading, empty, error and disabled states.



Do not immediately generate UI code without first understanding the existing product.



\## Social UX



For social features, prioritize:



\- Content readability

\- User identity

\- Social context

\- Interaction feedback

\- Discoverability

\- Clear information hierarchy

\- Fast content scanning

\- Mobile usability



\### Feed



The content is the primary focus.



Avoid making every post look like a dashboard card.



Like, comment and share actions should be obvious without competing with the content.



\### Profile



Clearly establish:



\- Avatar

\- Display name

\- Bio

\- Social actions

\- User content



Avoid unnecessary decorative containers.



\### Notifications



Clearly distinguish:



\- Read

\- Unread

\- Notification type

\- Timestamp

\- Related user/content



\### Chat



Prioritize:



\- Message readability

\- Sender identity

\- Message state

\- Conversation hierarchy



Consider:



\- Loading

\- Empty

\- Error

\- Offline

\- Sending

\- Sent

\- Failed



\## Typography



Use typography to establish hierarchy.



Avoid:



\- Too many font sizes

\- Excessive bold text

\- Decorative fonts that reduce readability

\- Weak contrast between primary and secondary information



\## Color



Use semantic color roles:



\- Background

\- Surface

\- Text

\- Secondary text

\- Border

\- Primary action

\- Success

\- Warning

\- Error



Do not introduce arbitrary colors for individual components.



\## Spacing



Use a consistent spacing rhythm.



Avoid random margins and padding.



Spacing should communicate relationships between elements.



\## Responsive Design



Design for:



\- Desktop

\- Tablet

\- Mobile



Do not simply shrink the desktop layout.



Reconsider navigation, content density, touch targets and component hierarchy on smaller screens.



\## Interaction States



Consider:



\- Default

\- Hover

\- Focus

\- Active

\- Disabled

\- Loading

\- Empty

\- Error



Users should always understand what is happening after an interaction.



\## Accessibility



Consider:



\- Semantic HTML

\- Keyboard navigation

\- Visible focus states

\- Accessible labels

\- Color contrast

\- Touch target sizes

\- Reduced motion



\## Motion



Use animation only when it improves:



\- Feedback

\- Orientation

\- State transitions

\- Spatial understanding



Do not add animation purely for decoration.



\## Final UI Audit



Before completing a UI, check:



1\. Does it look generic?

2\. Are there unnecessary cards?

3\. Are there unnecessary gradients?

4\. Is the visual hierarchy clear?

5\. Is the primary action obvious?

6\. Are loading, empty and error states handled?

7\. Does it work on mobile?

8\. Is accessibility considered?

9\. Are animations useful?

10\. Does it feel consistent with the existing Social product?



\## Implementation Workflow



Follow this order:



Understand

→ Inspect

→ Analyze UX

→ Define visual direction

→ Reuse existing components

→ Implement

→ Test responsive behavior

→ Test interaction states

→ Audit accessibility

→ Audit visual quality

→ Refine
